# Vibers Club — API Contract Outline

- **Status:** Draft v0.1, for review
- **Last updated:** 2026-10-25
- **Source of truth:** this outline until the backend exists; after that, the OpenAPI document generated by FastAPI (`/openapi.json`) is authoritative, and the TypeScript client in `packages/api-client/` is generated from it. This file then keeps only the conventions and the permission table.

## Conventions

| Topic | Rule |
| --- | --- |
| Base URL | `https://<api-host>/v1` |
| Auth | `Authorization: Bearer <Supabase access token>` on every endpoint except `/healthz`. The website reads the token from its Supabase session. CORS allows only the website's origins. The API verifies the token against Supabase's signing keys (JWKS), then loads our `users` row |
| Account state | Requests from `suspended` or `deletion_pending` users get `403 account_suspended` (except `GET /me` and `DELETE /me`) |
| Verification | Endpoints marked **V** need a verified phone; otherwise `403 verification_required` |
| Format | JSON, `snake_case`, UTC ISO 8601 timestamps, dates as `YYYY-MM-DD` |
| Errors | RFC 9457 problem JSON: `{"type", "title", "status", "code", "detail", "errors"?}`. `code` is a stable machine string such as `event_full` |
| Pagination | Cursor based: `?limit=20&cursor=<opaque>`, response `{"items": [...], "next_cursor": "..." or null}` |
| Idempotency | `POST` endpoints that create things accept an `Idempotency-Key` header; repeated keys within 24 hours return the original result |
| Rate limits | `429 rate_limited` with `Retry-After`. Per-user daily limits for business actions; per-IP burst limits on all routes |
| Versioning | Breaking changes go to `/v2`; additive changes stay in `/v1` |

Common error codes: `not_found`, `validation_failed`, `forbidden`, `verification_required`, `account_suspended`, `blocked`, `rate_limited`, `event_full` (only when the waitlist is closed), `already_registered`, `not_connected`, `under_age`, `conflict`.

## Endpoints

Legend: **V** = verified Viber required; **H** = event host only; **M** = moderator role.

### Health and lookups

| Method and path | Purpose |
| --- | --- |
| `GET /healthz` | Liveness and database check (no auth) |
| `GET /taxonomy` | Interest categories, interests, intents, version |
| `GET /areas` | Area list |

### Me (identity, profile, plan, vibe)

| Method and path | Purpose | Notes |
| --- | --- | --- |
| `POST /me` | Create our user record after first sign-in: `display_name`, `date_of_birth` | `422 under_age` if under 18; idempotent per auth user |
| `GET /me` | Own account, profile, plan, settings, verification state | |
| `PATCH /me/profile` | Name, bio, gender, visibility settings, `discoverable`, `women_only_discovery` | |
| `POST /me/photos/upload-url` | Get a signed upload URL for one photo (type and size limits) | Returns `upload_url`, `storage_path` |
| `POST /me/photos` | Register an uploaded photo at a position | Server checks the object exists, type and size |
| `DELETE /me/photos/{id}` | Remove a photo | |
| `PUT /me/travel-plan` | Status, area, dates, flexibility, intents, pace, budget | |
| `PUT /me/vibe` | Save vibe text; starts extraction | `202` with `vibe_status` |
| `GET /me/vibe` | Text, status, suggested interests and intents | App polls while `pending` |
| `PUT /me/interests` | Replace confirmed interests (1 to 15 ids) | |
| `POST /me/verification/sync` | Re-read phone verification from Supabase after the app completes phone OTP | |
| `POST /me/community-rules` | Accept community rules (needed before hosting) | |
| `GET /me/notification-preferences` / `PUT` | Per-type email on or off | |
| `DELETE /me` | Request account deletion (7-day grace period, then `delete_account` job) | |
| `GET /me/export` | Request a data export (emailed link in phase 2; MVP returns JSON) | |

### Discovery

| Method and path | Purpose | Notes |
| --- | --- | --- |
| `GET /discovery/vibers?limit=10` | Next cards: profile preview, photos, shared interests, explanation `{text, signals[]}` | Never returns contact details or exact dates if hidden |
| `POST /discovery/query` | `{text, corrections: {added[], removed[]}}` → `{thought: {chips, suggestions, confidence, explanation[]}, matches: [{viber preview, shared[], reasons[]}], pathways[]}` | Rules-first reading of the thought (synonyms, then LLM only when unsure); eligible Vibers only; no scores returned. Contract mirrors `apps/web/features/discover/types.ts` |
| `POST /discovery/swipes` | `{target_id, action: like or pass or save}` | Returns `{mutual: bool}` |
| `GET /discovery/saved` | Saved Vibers | |
| `GET /vibers/{id}` | Public profile view | `404` if not eligible to view (blocked, suspended, paused and not connected) |

### Connections and messaging

| Method and path | Purpose | Notes |
| --- | --- | --- |
| `POST /connections` **V** | `{target_id, note?}` | Daily limit; `409 conflict` if a request already exists |
| `GET /connections?status=pending_incoming or pending_outgoing or accepted` | Lists | |
| `POST /connections/{id}/accept` **V** | Accept; creates a conversation | Addressee only |
| `POST /connections/{id}/decline` | Decline | Addressee only |
| `DELETE /connections/{id}` | Remove an accepted connection, or cancel own pending request | |
| `GET /conversations` | Conversations with last message and unread count | |
| `GET /conversations/{id}/messages?after=<id>&limit=50` | Messages after an id (used for polling) | Participants only |
| `POST /conversations/{id}/messages` **V** | `{body}` | `403 not_connected` if the connection is gone or a block exists |
| `POST /conversations/{id}/read` | `{last_read_message_id}` | |

### Events

| Method and path | Purpose | Notes |
| --- | --- | --- |
| `GET /events?from=&to=&area=&interest=&pricing=free or paid&cursor=` | Browse upcoming events | |
| `GET /events/recommended?limit=20` | Ranked for the viewer, with explanation | |
| `POST /events` **V** | Create (published immediately) | Community rules accepted; new-host limit; property must be managed by the host |
| `GET /events/{id}` | Details, seats left, host summary, viewer's registration, attendee preview (respecting settings) | |
| `PATCH /events/{id}` **H** | Edit; time or place changes notify registrants | Capacity cannot drop below confirmed count |
| `POST /events/{id}/cancel` **H** | `{reason}`; notifies registrants | |
| `POST /events/{id}/registrations` | Register: confirmed, or waitlisted when full | Locks the event row; `409 already_registered` |
| `DELETE /events/{id}/registrations/me` | Cancel own registration; promotes waitlist | |
| `GET /events/{id}/registrations` **H** | Registrant list (name, photo, status, payment, attendance) | |
| `PATCH /events/{id}/registrations/{rid}` **H** | `{payment_status?, attendance?}` | |
| `POST /events/{id}/updates` **H** | Send a short update to registrants (in-app plus email) | Daily limit per event |
| `GET /me/events?role=hosting or attending&when=upcoming or past` | Own events | |

## Permission matrix (summary)

| Action | Any signed-in | Verified Viber | Host of event | Moderator |
| --- | --- | --- | --- | --- |
| Browse discovery, events, places | Yes | Yes | Yes | Yes |
| Swipe, save, RSVP | Yes | Yes | Yes | Yes |
| Send or accept connection request, message | No | Yes | — | — |
| Create event or property | No | Yes | — | — |
| Edit, cancel event, manage registrations | No | No | Yes | Hide only |
| Review an event | Confirmed attendees only, not the host | | | |
| Hide content, suspend users | No | No | No | Yes |

Every rule above is enforced in the service layer and covered by an authorization test ([TESTING_STRATEGY.md](TESTING_STRATEGY.md)).
